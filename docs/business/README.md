# Business Documentation

## Purpose

This area answers **why TransferX exists as a business**: the problem it addresses, who it serves commercially, and how it intends to make money. It is deliberately non-technical.

## Scope

In scope: vision/mission, target market, business model, and a shared glossary of domain terms used across all documentation.
Out of scope: what features to build and when (see [`../product/`](../product/README.md)), how the system is built (see [`../architecture/`](../architecture/README.md)).
